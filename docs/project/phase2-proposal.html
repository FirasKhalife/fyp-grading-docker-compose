FYP Grading: what to build before it goes live

I ran the slim stack, walked every screen, and read all 11 repos. The short version: the architecture is a good story, but on master the product doesn't work. Nobody can log in, the grading pipeline fails at four separate points, and every admin read is public. The frontend was written against an older backend and was never updated. So the proposal is: make the core flow work and safe first, then rebuild the frontend on top of it, then add the features that make a 5-minute visit memorable.

What I found

The product, as a visitor sees it

  • Six screens: login, home, an "evaluate" dialog, the grading form, an admin team list, and a rubric page. Home is three grey bands of identical buttons labelled TEAM 1, TEAM 2 (the database has names, the API doesn't return them). There's a visible typo, "Avdisor assessment".
  • Grading is four dropdowns per rubric (Exemplary 4 → Beginning 1) with no level descriptions, no comment, no running score, and validation through window.alert. Null grades slip past the check.
  • Rubric editing is a full-screen raw JSON textarea.
  • Admin results are plain text lines like "Final Report (30%): 81/100". No table, no progress, no state.
  • No branding, no explanation of what the app is, no mobile layout, no dark mode, no empty or loading states.

Why it doesn't work today

  • Login: the frontend POSTs to /api/auth/login, which was removed in the Keycloak move. Any failure shows "Invalid email or password". There's also no realm import, and seeded reviewers have random UUIDs that can never match a Keycloak user.
  • Frontend ↔ backend drift: the frontend calls /reviewers/{id}/home (backend: /reviewers/home), types reviewer ids as numbers (backend: UUIDs), uses JURY_MEMBER (backend: JURY). The auth header is computed once at module load, so even a valid token isn't sent until a reload.
  • Grading pipeline, four independent breaks: evaluation-service's Feign client posts to /api/ instead of /api/grades/; admin-service merges an entity outside a transaction in the RabbitMQ consumer (retries 5×, then dead-letters); that merge would also wipe the team name; and evaluation-service expects a rubric shape that rubric-service doesn't return. Several read endpoints also fail on bad JPA mappings.
  • Security: @RolesAllowed is inert (no @EnableMethodSecurity anywhere) and GETs are open, so I listed every reviewer's email through the gateway with no token. Actuator exposes everything including heapdump and shutdown, and the gateway routes it. Grading trusts reviewerId from the request body. A Keycloak client secret is committed.

The code, as a senior reviewer sees it

  • Tests: 5 in the whole system, all contextLoads, and admin-service's is excluded from the build. The one real test was deleted. The frontend has none.
  • Duplication: AuthoritiesConverter ×6, SecurityConfig/RestExceptionHandler/LoggingAspect ×4, AssessmentEnum ×4, hand-copied DTOs that have already drifted, 10 near-identical gateway routes.
  • API design: every collection is mapped to "/" (so /api/rubrics is a 404 on Spring 6), creates return 200, no validation, no pagination, no OpenAPI, bare {status,message} errors. Audit columns always say SYSTEM.
  • Docs: no README in any service. The frontend README is the Vite template.
  • Versions: Spring Boot 3.1.5 / Cloud 2022.0.4 (config-server alone is on 3.3.3), Java 17, Node 18, Vite 4, ESLint 8. All out of support.
  • Terraform: one 714-line main.tf that would fail at apply (empty key, invalid CIDR, both EIPs on one instance) and wouldn't work if fixed (no route to the internet, egress allows only port 0, no Keycloak). SSH is open to the world on 8 instances.
  • CI: a broken Jenkinsfile on admin-service, copies of it on three add_*_pipeline branches, and a GitHub workflow on deprecated v3 actions. Left for the CI phase as agreed. Every other remote branch is fully merged and could be deleted later (your call).
